# Matching evaluation, 2026-10-04

Result: the frozen config `lexical-2.0` fails the precision gate on the exam. Match suggestions stay off (`RESCRIBO_MATCH_SUGGESTIONS_ENABLED=false`). This report makes no claim that the local matcher is good enough to show suggestions.

Requirements: `openspec/specs/matching-evaluation/`. Gates: `eval/matching/gates.json`. Raw results: `eval/matching/results/`.

## Conditions

- Data: synthetic only, generated by `openai/gpt-6.1-sol`, each batch spot-checked on 20 cases. One fictional workspace of 20 problems per batch, 0 to 3 linked reports per problem. No real customer text.
- Practice (tuning): `practice-20261004-c80b`, 122 cases. Exam (scored once): `exam-20261004-3f8e` and `exam-20261004-acae`, 244 cases.
- Exam class balance: match 40, paraphrase 40, confusable 24, missing_context 40, misleading_version 40, negation 40, no_match 20. 184 cases expect a problem; 60 expect no match.
- Candidate pools: the PostgreSQL retrieval used by the product (`scripts/eval_baseline.py`), at most ten. Rust, PostgreSQL order, and Jev all rank the same pools.
- Intervals are 95% Wilson score intervals.

What fails:

- Negation: 24 of 40 reports that say a listed problem is fixed still get it suggested. `lexical-2` drops clauses with words such as "fine", "works", and "no longer". It cut practice negation false suggestions from 20/20 to 5/20, but exam reports state the fix in other words.
- Confusable: 19 of 24 rank the sibling problem first. Token overlap cannot separate two problems that share most of their words.
- Paraphrase: 1 of 40 right. The thresholds that keep precision up make the matcher abstain on reworded reports.
- Missing context and misleading version: most abstain, because short or noisy reports score under `min_score`.

Step through them with `task eval:review -- exam-20261004-3f8e+exam-20261004-acae-rust-lexical-2.0.json`.

## Jev baseline

- Model: `typesafe/jev-1.13` requested, `typesafe/jev-1.13-20260917` served on every call. Decisions API (alpha), one Choice per case over the pool plus "none". Problem title and summary only; IDs never sent.
- Repeat runs agreed on 243 of 244 cases (same top suggestion or both abstained). The API documents no seed or temperature.
- Cost: $0.011813 per exam run (281,269 input tokens). Practice run $0.005691; smoke test $0.000467. One exam run was lost to a dropped connection before completing.
- Jev runs in evaluation tooling only (`scripts/eval_jev.py`). The product makes no hosted model call; ADR 0003 stands.

Jev's result says the exam cases are separable from text alone, which is the headroom over lexical ranking. It does not say how Jev would do on real reports: the cases were written by another large model and may suit models more than real customer writing does.

## Limitations

- Synthetic data from one generator model and one prompt version. Real reports may differ in length, vocabulary, and noise.
- 20 problems per workspace. Recall and ranking in larger workspaces are untested; the ten-candidate limit still needs a larger batch before suggestions are shown.
- One practice batch of 122 cases. Practice intervals are wide (about ±0.10).
- Deployment limits (5 s timeout, 64 KiB response) are still provisional.
