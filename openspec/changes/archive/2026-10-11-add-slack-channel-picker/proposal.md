# Proposal

Delivers GitHub issue #148, "[Check] Allowing a Slack channel needs a raw channel ID".

## Why

An owner who wants to allow a Slack channel must type its raw ID. The form does not say what an ID is or where to find it. The consent box that enables the submit button sits higher in the card, off screen from the field. The whole control sits below Reconnect, Check status, and Disconnect.

The spec says an owner approves channels "by ID or link". Links have never been accepted: `ChannelInputSerializer` matches `^[CG][A-Z0-9]+$` only.

## What Changes

- The owner picks a channel by name from the channels the bot is in. The list comes from Slack through a new owner-only endpoint, `GET /api/workspaces/{id}/channels/`.
- Slack Connect channels the bot is in show in the list as unavailable, with the reason. Archived channels are left out.
- The server still checks the chosen channel with `conversations.info` and the existing policy when it is submitted. The list in the browser is never trusted. The `POST` contract does not change.
- The raw "Slack channel ID" field goes. The API still takes a channel ID.
- The channel form gets its own publication notice and confirmation box, beside the channel choice. The connect form keeps its own box.
- The "Allowed Slack channels" section moves above Reconnect, Check status, and Disconnect.
- The list shows a loading state, an empty state that says to invite the app, and an error state with a retry. A rate limit from Slack reads as "try again in a minute".
- With `RESCRIBO_SLACK_FAKE_DELIVERY` on, the list and the submit-time check use a small fixed set of fake channels, so development and e2e run without Slack. The demo workspace refuses the list before any Slack call.
- No new scopes, no migration.

The consent, placement, fallback, and unavailable-channel points follow the recommended answers to Q1 to Q4 in `design.md`. They change if the maintainer answers otherwise.

## Capabilities

### New Capabilities
None.

### Modified Capabilities
- `slack-connection`: "Approved capture channels" drops "by ID or link" and says the owner chooses from a list and the server checks the choice. Adds "Channel choice list", "Channel choice list states", and "Channel approval placement and notice".
